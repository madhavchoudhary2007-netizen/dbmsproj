# PACKET T-44596
role: Worker 2 — State/Runtime. State/runtime code only; never components or tests.

## Task
Implement the schema migration ledger (Phase 3 T-335).
Create table `schema_migrations(version VARCHAR(64) PRIMARY KEY, checksum VARCHAR(64) NOT NULL, applied_at TIMESTAMPTZ NOT NULL DEFAULT NOW())`.
Extract migration execution and ledger management into `backend/app/migrations.py`.
In `bootstrap.py`, invoke migration execution:
1. Apply each numbered `.sql` migration file in version order inside a transaction (`with conn.transaction(): ...`).
2. Verify SHA-256 checksums of migration files. If a file was already applied and its recorded checksum differs from the file's current SHA-256 hex digest, raise `RuntimeError(f"Checksum mismatch for migration {version}: expected {recorded}, got {current}")`.
3. If not applied, execute the SQL and record `(version, checksum, NOW())` in `schema_migrations`.
4. For existing databases where application tables (e.g. `championships`) already exist but `schema_migrations` does not contain prior migration entries, backfill entries for existing migrations `001_initial.sql`, `002_*.sql`, `003_*.sql` (after verifying sentinel table exists) with their current checksums so they are not re-executed erroneously.
5. Seed demo data only when `SEED_DEMO_DATA` is true.
6. Keep `bootstrap.py` as entrypoint clean and strictly <= 120 lines.
