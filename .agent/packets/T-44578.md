## Acceptance criteria
1. `stewards.py` and `pit_write.py` define domain `APIRouter` instances (`router`) with endpoints using FastAPI dependencies:
   - `stewards.py`:
     - `/api/incidents` (GET) -> handler `get_incidents`
     - `/api/incidents` (POST) -> handler `create_incident`
     - `/api/incidents/{incident_id}/decision` (POST) -> handler `decide_incident`
   - `pit_write.py`:
     - `/api/pit-reservations` (POST) -> handler `reserve_pit`
     - `/api/pit-reservations/auto` (POST) -> handler `reserve_pit_auto`
     - `/api/pit-reservations/{reservation_id}` (PATCH) -> handler `update_pit_reservation`
2. Database access uses `get_race_db` (or `DatabaseSession`) via `Depends(get_race_db)` and connection context where required.
3. Simulations and event bus access use `Depends(get_simulations)` and `Depends(get_bus)` or fallback to app runtime state.
4. Auth uses `admin_steward_dependency = Depends(require_roles("ADMIN", "STEWARD"))` (or `main.admin_steward`), `admin_steward_principal_dependency = Depends(require_roles("ADMIN", "STEWARD", "PRINCIPAL"))`, and `authenticated_user_dependency = Depends(current_user)`.
5. Exported aliases on `main.py` (`get_incidents`, `create_incident`, `decide_incident`, `reserve_pit`, `reserve_pit_auto`, `update_pit_reservation`, `stewards_handlers`, `_pit_write_handlers`) remain accessible for backwards compatibility.
6. `main.py` directly mounts the router(s) without intermediate positional assembly lambda blocks. `operations_routes.py` is folded into router exports / a thin compatibility wrapper.
7. Factory functions `create_stewards_router` and `create_pit_write_router` remain available for backwards compatibility.
8. OpenAPI schema matches snapshot exactly; route registrations are unique; strict mypy, ruff check, and ruff format pass with zero errors.
