## Acceptance criteria
1. `session_action.py`, `results_read.py`, and `results_write.py` define domain `APIRouter` instances (`router`) with endpoints using FastAPI dependencies:
   - `session_action.py`:
     - `/api/sessions/{session_id}/action` (POST) -> handler `session_action`
   - `results_read.py`:
     - `/api/sessions/{session_id}/results` (GET) -> handler `results`
     - `/api/championships/{championship_id}/recalculate` (POST) -> handler `recalculate`
     - `/api/championships/{championship_id}/standings` (GET) -> handler `standings`
   - `results_write.py`:
     - `/api/sessions/{session_id}/results` (POST) -> handler `save_results`
2. Database access uses `get_race_db` (or `DatabaseSession`) via `Depends(get_race_db)` and connection context where required.
3. Simulations and event bus access use `Depends(get_simulations)` and `Depends(get_bus)` or fallback to app runtime state.
4. Auth uses `admin_steward_dependency = Depends(require_roles("ADMIN", "STEWARD"))` (or `main.admin_steward`) and `authenticated_user_dependency = Depends(current_user)`.
5. Exported aliases on `main.py` (`session_action`, `results`, `standings`, `recalculate`, `save_results`, `session_action_handlers`, `results_read_handlers`, `results_write_handlers`) remain accessible for backwards compatibility.
6. `main.py` directly mounts the router(s) without intermediate positional assembly lambda blocks. `race_operation_routes.py` is folded into router exports / a thin compatibility wrapper.
7. Factory functions `create_session_action_router`, `create_results_read_router`, and `create_results_write_router` remain available for backwards compatibility.
8. OpenAPI schema matches snapshot exactly; route registrations are unique; strict mypy, ruff check, and ruff format pass with zero errors.
