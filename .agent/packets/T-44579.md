## Acceptance criteria
1. `auth_router.py` and `user_router.py` define domain `APIRouter` instances (`router`) with endpoints using FastAPI dependencies:
   - `auth_router.py`:
     - `/api/auth/login` (POST) -> handler `login`
     - `/api/auth/logout` (POST) -> handler `logout`
     - `/api/auth/me` (GET) -> handler `me`
     - `/api/auth/refresh` (POST) -> handler `refresh`
   - `user_router.py`:
     - `/api/users` (GET) -> handler `users`
     - `/api/users/{user_id}` (GET) -> handler `get_user`
     - `/api/users` (POST) -> handler `create_user`
     - `/api/users/{user_id}` (PATCH) -> handler `update_user`
     - `/api/users/{user_id}` (DELETE) -> handler `delete_user`
2. Database access in auth endpoints uses `get_race_db` (or `DatabaseSession`) via `Depends(get_race_db)` and connection context where required.
3. User endpoints use `admin_user = Depends(require_roles("ADMIN"))` (or `main.admin_role_dependency`).
4. `main.py` directly mounts `app.include_router(auth_router)` and `app.include_router(user_router)`.
5. Factory functions `create_auth_router` and `create_user_router` remain available and functional for backwards compatibility (especially with `test_login_throttle.py`).
6. Exported aliases on `main.py` remain accessible for backwards compatibility.
7. OpenAPI schema matches snapshot exactly; route registrations are unique; strict mypy, ruff check, and ruff format pass with zero errors.
